# AIGC视频项目后端服务
基于Python+Flask搭建的AIGC视频自动化工作流后端服务，提供视频列表查询、详情查询及视频创建接口，通过Faker生成模拟数据，支持Vercel平台一键部署。

## 项目信息
- 项目名称：AIGC视频自动化工作流后端服务
- 技术栈：Python + Flask + Faker（Mock数据）
- 项目类型：RESTful API后端服务
- 部署平台：Vercel（免费托管，支持Python项目一键部署）

## 演示地址(建议使用本地运行验证)
- 前端在线地址：[https://aigc-video-project-frontend.vercel.app](https://aigc-video-project-frontend.vercel.app)
- 后端API地址：[https://aigc-video-project-backend.vercel.app](https://aigc-video-project-backend.vercel.app)
- 前端页面：http://localhost:5173（启动前端服务后访问） 
- 后端API接口：http://127.0.0.1:5001/api/videos（启动后端服务后访问）
- 网关服务：http://127.0.0.1:5002（启动网关服务后访问）
## 技术说明
1. 后端框架：Flask（轻量级Web框架，快速实现RESTful API开发）
2. Mock数据：使用Faker生成模拟的视频列表、视频详情数据，无需依赖真实数据库
3. 部署方式：Vercel免费托管，支持Python项目的自动化构建与部署
4. 跨域处理：集成flask-cors解决前端跨域请求拦截问题

## 开发过程问题与解决记录
1. 跨域问题：前端调用后端接口出现CORS报错 → 解决方案：安装flask-cors库，在app.py中配置`CORS(app)`开启全局跨域
2. 部署问题：Vercel部署Python项目时路径识别失败 → 解决方案：编写vercel.json配置文件，指定项目构建规则与入口文件
3. 数据问题：无真实数据库时接口返回空数据 → 解决方案：使用Faker库封装模拟数据生成函数，为所有接口提供可用的测试数据

## 本地运行步骤
1. 克隆项目：`git clone [项目仓库地址]`（若有Git仓库）
2. 进入项目目录：`cd backend`

   - Linux/macOS：`source venv/bin/activate`
5. 安装项目依赖：`pip install -r requirements.txt`
6. 启动后端服务：`python app.py`
7. 调试接口：浏览器访问 [http://127.0.0.1:5001/api/videos](http://127.0.0.1:5001/api/videos) 即可查看返回数据

## 项目开发过程笔记
### 1. 简述项目实现思路
本项目是「前后端分离 + 网关代理」的 AIGC 视频管理系统，核心逻辑如下：
- 后端：基于 Flask 搭建 RESTful API，提供视频列表查询、视频创建核心接口，通过 mock_data.py 模拟真实业务数据；
- 前端：采用 Vue+Vite 构建页面，实现视频列表渲染、详情页跳转、视频创建提交等交互功能；
- 网关：配置请求转发规则，解决前后端跨域通信问题；
- 验证：优先通过本地服务联调确保功能可用，再尝试免费平台部署上线，最终以「本地可运行代码 + 截图」完成功能验证。

### 2. 遇到的问题与解决方案
| 遇到的问题 | 解决方案 | 技术收获 |
| :--- | :--- | :--- |
| 前端调用后端接口出现跨域报错 | 1. 后端 Flask 添加 `flask-cors` 跨域配置；2. 网关层设置转发允许跨域；3. 前端接口请求地址指向网关或本地后端 | 理解跨域产生的底层原理，掌握前后端+网关三层跨域解决方案 |
| 线上部署的后端地址频繁失效（免费平台休眠机制） | 1. 放弃依赖不稳定的在线地址，改用本地后端服务（127.0.0.1 开头）完成功能验证；2. 截图保留完整本地地址栏；3. 在 README 标注在线地址休眠问题 | 明确免费部署平台的局限性，优先保证本地代码可运行性（面试官核心关注维度） |
| 前端页面无法加载视频列表数据 | 1. 排查发现接口地址配置错误（仍指向失效的线上地址）；2. 修改为本地后端地址 `http://127.0.0.1:5001/api/videos`；3. 重启前端服务后数据正常加载 | 形成「核对配置→检查服务状态→排查代码」的标准化调试逻辑 |
### 3. 本地联调的经验
- 联调顺序：先启动后端服务（验证 API 接口返回 JSON 数据）→ 启动网关服务（测试转发规则生效）→ 启动前端服务（验证页面与接口交互），避免跨服务依赖导致问题定位困难；
- 接口调试技巧：直接通过浏览器地址栏访问后端 API 地址，快速判断问题归属（接口本身问题 / 前端调用问题）；
- 配置统一原则：提前约定前后端、网关的端口号（如后端 5001、前端 5173、网关 8080）和接口路径前缀（如/api），减少联调时的配置冲突；
功能验证优先级：先确保核心功能（列表加载、详情页、创建接口）可用，再优化细节，提高联调效率。
### 4. 部署步骤与踩坑记录
本地部署步骤（推荐，稳定可靠）
- 后端部署：
进入backend目录，执行pip install -r requirements.txt安装依赖；
执行python app.py启动服务，访问http://127.0.0.1:5001/api/videos验证接口；
前端部署：
进入frontend目录，执行npm install安装依赖；
执行npm run dev启动服务，访问http://localhost:5173验证页面；
- 网关部署：
1. 进入gateway目录，执行对应启动命令（如node app.js）；
确认转发规则生效，前端可通过网关访问后端接口。
2. 在线部署步骤（可选，免费平台）
- 后端：部署至 Render 平台，配置vercel.json指定启动命令（python app.py）和端口；
- 前端：部署至 Vercel 平台，关联 GitHub 仓库自动构建；
- 网关：部署至 Fly.io 平台，配置转发地址指向在线后端。
3. 部署踩坑记录
- Render 平台部署后端时，因未配置启动命令导致部署失败 → 解决方案：在vercel.json中添加"scripts": {"start": "python app.py"}，并指定平台兼容端口；
- 前端在线部署后，因后端服务休眠导致数据加载失败 → 解决方案：优先推荐本地验证，在 README 明确标注在线部署的局限性。
